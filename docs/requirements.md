# 要件定義（日本語・個人用）

## 対象と運用
- 個人のMacで動作するlocalhost専用Web家計簿。日本語・日本円。金額は整数円、明細は数量を含む税込合計。
- 初回は分類のみ初期設定し、取引・レシートは空。架空の本番データは作らない。
- 将来のiPhoneを考慮したレスポンシブ画面。現段階ではMac以外から接続できない。LAN公開は仕様外。
- 提供された実レシート2枚でローカル取り込みと転記額の配賦を検証。外部OCR精度と大量処理負荷は未検証。

## 取り込み
1. 利用者が指定したGoogle Driveフォルダの直下を手動ボタンで取得。読み取り専用OAuth。ページネーション。サブフォルダは再帰しない。
2. JPEG、PNG、HEIC/HEIFの手動アップロードを代替経路とする。12MiB、25百万画素上限。画像は表示・OCR用JPEGへ変換、EXIF回転補正、最大辺3000px。
3. DriveファイルIDと元のファイルバイト列SHA-256で重複を防ぐ。同内容別名も重複。同じ画像を再圧縮したものは別バイト列なので対象外。
4. Driveの同じIDの更新版は再取得しない。更新版を取り込みたい場合は別IDまたは手動アップロード。削除・Driveへの書き込みは行わない。

## 認識と確認
- 初期推奨は「無料OCR（Mac内で処理）」。macOS Apple VisionをSwift CLIで実行し、APIキー/外部送信同意に依存しない。画像を送信せず、有料AIへ自動フォールバックしない。
- 日付・店名・明細・印字税抜/割引/税総額を位置と文字列から保守的に解析。不明/低信頼価格はnull、税込明細と全商品共通税率は未確定。数量表記がない商品行の1は仮値として警告。差額・単価から価格を作らない。
- 無料OCR分類はローカルの完全一致商品名ルールのみ。未知は未分類。原文・座標・信頼指標を保存し、原文表示・下書き編集・手動確認・既存配賦モデルを維持する。
- 初回Swiftコンパイル120秒、画像認識60秒の上限。引数リストで実行しshellを使わず、SHA256名の内部画像以外・シンボリックリンクを拒否。未対応環境では明確に手入力を案内する。
- 外部OCRはOpenAI Responses APIの画像入力＋厳密JSON schema。APIキー・モデル設定・有料サービス同意がすべて揃うまで無効。
- 費用の上限や単価をアプリで推測しない。モデル選択と公式料金確認を利用者が行う。各OCR操作でも送信確認を表示。バッチOCR・自動OCR・課金APIの自動再試行なし。
- 商品分類には編集可能な名前と説明を送る。確定時に商品名の完全一致ルールをローカル保存し、次回OCR結果に優先適用。
- 画像と入力画面を並べ、日付・店名・商品名・分類・税込明細額・合計を編集。手入力、下書き保存、確定後の再編集が可能。
- 税別は印字税抜額・数量とレシート総額/割引/税を保持し、税込額は当初null。単一税率のみ最大剰余法の配賦案を提示し、明示適用・承認後に確定可能。不明価格を逆算しない。混在税率・欠落・負の税抜額・割引超過・不一致では配賦拒否。値が揃っても明示的な確認チェックが必要。
- 空明細・欠落値・無効分類・不正日付・非整数・合計不一致では確定しない。割引は負数の明細で扱えるがレシート合計は非負。
- OCR応答全文をDBに保持。直近は画面表示、全試行はocr_runsに監査保存。確認後も警告は保持する。

## 集計と保存
- 確定済みだけを月次・分類別・日次分類別に集計。月選択、全日（ゼロの日も）を表示する。
- SQLiteトランザクションで確定・整数円仕訳・ルール更新をまとめる。再編集時は集計対象から外す。
- CSVはUTF-8 BOM、式注入文字を先頭アポストロフィで無害化。月内確定明細のみ。
- SQLite backup APIとアプリ内排他でDBと全画像の一貫したZIPを作る。OAuth/APIの秘密ファイルは含めない。

## 安全性・非目標
- 127.0.0.1だけにbind、localhost Host検査、変更操作に同一Origin必須。CSP、DOM textContent、安全なパラメータ化SQL。
- 任意ファイルパスをHTTPで指定できない。拡張子だけでなくデコード形式・容量・画素数も検証。
- 秘密はサーバー側.env / data内のみ。既存Hermesの資格情報は読まない。初回OAuthはこのアプリ用の独立クライアントで行う。
- インターネット公開、複数ユーザー、会計/税務申告、電子帳簿保存法対応、暗号化DB、クラウド同期、完全な重複画像検出は対象外。
- バックアップZIP・CSVには私的情報がある。ユーザーが安全な場所に保管する。

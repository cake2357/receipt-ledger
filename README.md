# レシート家計簿 — Mac ローカル版

日本語 / JPY。レシート画像の取り込み、無料のMac内OCRと任意の有料AI OCR、**必ず人が確認してから確定**する家計簿です。最初は分類以外のデータは空です。iPhone幅の画面に対応していますが、現在はMacのlocalhost専用です。

## 起動（最短）

[uv](https://docs.astral.sh/uv/getting-started/installation/) とPython 3.12以降が必要です。依存は `uv.lock` で固定しています。

```sh
cd /Users/yoshiki2357/receipt-ledger
./run.command
```

ブラウザで **http://127.0.0.1:8765** を開きます。Finderで `run.command` をダブルクリックでも起動できます。初回は依存を取得するためインターネット接続が必要です。終了はターミナルで `Ctrl+C`。

`run.command` は自分のフォルダへ移動して `uv run --frozen python server.py` を実行します。`uv` がPATHになくても `$HOME/.local/bin/uv` を探します。**0.0.0.0への公開は禁止**。8765が使用中なら `.env` の `LEDGER_PORT` を変更し、そのポートのURLを開きます。

## 基本操作

1. 「レシート」→「画像を追加」、または「手入力で追加」。JPEG/PNG/HEIC（12MiBまで、25百万画素まで）に対応。
2. 画像は画面表示・OCR用にJPEGへ変換し、EXIF回転補正、最大辺3000pxへ縮小。元ファイルはDrive/手元に残してください。アプリには変換後画像を保存します。
3. 日付、店名、商品名、分類、**各明細の税込合計金額（数量込み）**、レシート合計を入力。
4. 未完成のまま「下書きを保存」できます。税別レシートは下記の配賦案を確認して明示適用できます。通常の税込手入力では割引を負の明細で入力できます。
5. 確認チェックを付けて「確認して保存」。欠落値・小数・合計不一致では確定できません。
6. 確定後は「再編集する」で下書きへ戻せます。その間は集計対象外。
7. 「分類・設定」で分類名と説明を変更/追加。確定した商品名の完全一致ルールを次回OCR分類に優先適用します。
8. 「家計の概要」で月を選択。分類別月次・分類別日次グラフ/表を表示。支出ゼロの日も含みます。

## 画面の操作順と計算の確認

- **1. レシートを入力 → 2. 合計を確認して保存**の順です。無料のMac内OCRが標準経路、有料AI OCRは任意です。手入力でも利用できます。
- 商品名・分類・税抜/税込明細額・数量・税率・OK割引対象には常に見えるラベルがあります。税抜/税込額は**数量込みの明細合計**で、単価ではありません。
- 通常は日付・店名・商品名・分類・税込金額・レシート合計を入力します。まとめて分類する操作は必要なときだけ開きます。
- 「商品の金額が税抜で書かれている」を選ぶと分類別の8%/10%計算を表示。OK食品割引は適用なし・3/103・印字割引額から選択し、案を見てから明示適用します。印字割引額は、その方式を選択した場合と別の計算方法を開いた場合だけ表示します。
- 従来の手動配賦は「別の計算方法：レシートの税額を使う」を開いて使用。全商品0%・8%・10%のいずれかのみで、混在税率には使えません。計算値への承認欄は詳細を開かずに操作できます。
- 入力変更後は案と承認を解除し、前回の計算は再計算が必要と表示します。税込欄は勝手に書き換えません。分類設定の変更など、保存済み計算の有効性は確定時にもサーバーで検証します。
- 保存・計算・OCR中は操作を一時停止し二重送信を防止。保存結果とエラーは確認ボタンの近くにも表示します。計算案の表示は入力を下書き保存しますが、案の適用・確定は別操作です。
- 差額0円だけでは正しい保証になりません。不明価格を差額で埋めず下書きで保存し、画像・税率・割引対象・転記額を確認してください。店舗固有の単品丸め、実iPhone Safariは未検証です。

この画面更新だけなら**ブラウザの再読み込み**で反映します。古いPython版を起動したままの場合だけ従来の再起動手順が必要です。`.env`・本番データ・税計算ルールは変更していません。

## 税別レシートの割引・税配賦

1. 「税別レシート」を選び、「別の計算方法：レシートの税額を使う」を開きます。全商品の税率（単一の0/8/10%）を印字で確認します。混在税率・不明税率はこの手動配賦では利用できません。
2. 各行に**数量込み税抜明細額**と数量を入力。割引前合計、正数の割引総額、税総額、税込合計を転記。割引後小計と点数は任意ですが入力した場合は一致検証します。不明値は空欄のまま保存してください。
3. 「商品の税込金額を確認する」は入力を下書き保存したうえで、案だけを表示します。明細額はまだ変更しません。「この金額を商品に反映する」で初めて計算値を保存します。
4. 元の税抜額、配賦割引・税、計算値の由来（`largest-remainder-v1`）を保持。配賦への承認と通常の確認チェックを付けて確定します。入力変更後は再計算が必要です。

計算は整数円の最大剰余法：割引総額を税抜額の比率で配分し、税総額を割引後金額の比率で配分。同じ剰余は明細順で優先します。合計を保存しますが、**店舗の単品別丸めや個別割引対象を再現するものではなく、家計簿上の比例配賦**です。3/103割引を3%へ置き換えません。不明価格を合計との差額で埋めません。割引超過・負の税抜額・欠落・不一致は拒否します。税率混在のグループ別配賦は未実装です。

iPhone HDR JPEGをPillowがMPOと認識する場合も主画像を取り込みます。補助画像は保存しません。

## Google Drive（任意・手動取り込み）

**既存のHermesや他アプリのトークン/秘密情報は使いません。** 自分専用のGoogle CloudプロジェクトとOAuth Desktopクライアントを作成してください。

1. [Google Cloud Console](https://console.cloud.google.com/) で自分用プロジェクトを作成/選択。
2. 「APIとサービス」→「ライブラリ」で **Google Drive API** のみを有効化。
3. Google Auth Platformの「ブランド」「対象/オーディエンス」を設定。個人利用でExternal/Testingなら自分のGoogleアカウントをテストユーザーに追加。Testing状態のトークンは期限切れになることがあります。組織アカウントは管理者の許可が必要な場合があります。
4. 「クライアント」→OAuthクライアントを作成→ **デスクトップアプリ**。Webアプリではありません。
5. JSONをダウンロードし、このアプリの `data/google-client.json` として保存。`mkdir -p data` でフォルダを作り、ファイルの権限を `chmod 600 data/google-client.json` にします。
6. このフォルダで実行：
   ```sh
   uv run --frozen python oauth_setup.py
   ```
   ブラウザが開くので自分のアカウントで許可。PKCEと動的ポートの127.0.0.1コールバックを使用します。コード/パスワードをチャットに貼らないでください。180秒でタイムアウトした場合は再実行。
7. `data/google-token.json` にこのアプリ専用トークンを権限600で保存。要求scopeは **https://www.googleapis.com/auth/drive.readonly** のみ。Drive全体への読み取り権限ですが、取り込みコードは指定フォルダの直下だけを一覧取得します。
8. Driveで対象フォルダを開き、URL `https://drive.google.com/drive/folders/FOLDER_ID` の `FOLDER_ID` 部分だけを「分類・設定」に保存。
9. 「レシート」→「Driveから取り込む」。一覧を全ページ処理。対応画像だけ取得し、下書きを作成。OCRは実行しません。

サブフォルダ/PDF/Googleドキュメントは対象外。ファイルIDおよび元ファイルSHA-256で重複排除。同じIDのファイルを更新しても再取り込みしません。エラー分は次回ボタンで再試行できます。一部取り込み後に通信失敗した場合も成功分は保持します。

認証切れ/取り消し時はセットアップを再実行。解除したい場合はGoogleアカウント側でこのアプリのアクセスを取り消し、サーバー停止後に `data/google-token.json` を削除してください。`LEDGER_DATA_DIR` を変更した場合、OAuthセットアップは標準 `data/` に保存するため、その二つの資格情報ファイルを選択したデータフォルダへ手動で移してください。

## 無料OCR（Mac内で処理）— おすすめの初期経路

**Apple VisionをこのMac内で実行します。APIキー・有料送信の同意は不要で、画像を外部に送信せず、API利用料も発生しません。** 「有料AI OCR」とは別機能です。外部サービスへ自動で切り替えません。

1. MacにXcode Command Line Toolsが必要です。未導入なら `xcode-select --install` を実行してAppleの案内に従います（開発ツールの取得にはネット接続が必要）。日本語対応はVisionの `supportedRecognitionLanguages()` で実行時に確認します。検証環境はApple Silicon・macOS 26.6.2・Swift 6.3.3です。他のmacOS版/Intelは未検証です。
2. 既にアプリを起動している場合、更新したPythonコードを反映するため一度 `Ctrl+C` → `./run.command` で再起動。**既存の `.env`、`data/`、ポート設定は変更しないでください。現在8888を設定している場合は http://127.0.0.1:8888 を使います。**
3. 画像付き下書きを開き、上部の **「画像から読み取る（無料）」** を押します。現在の入力を置き換える確認が出ます。取り込みだけではOCRも確定も実行しません。
4. 初回またはSwiftソース更新後だけ、同梱 `native/vision_ocr.swift` を `xcrun swiftc` でコンパイル（上限120秒）。実行ファイルはGit対象外 `artifacts/local-ocr-cache/` に保存し、次回から再利用。画像認識は1回60秒で打ち切ります。通常の起動時にはコンパイルしません。
5. 「認識した文字（無料OCR原文）」と画像を見ながら下書きを修正します。日付・店名・商品名・印字金額を簡易解析しますが、**AIの意味理解ではなく、レイアウトに依存する転記補助**です。傾き・薄い価格・文字の取り違え・欄の対応ミスがあり、税込明細額は空欄、全商品の税率も未確認にします。数値が入っていても正しい保証はありません。
6. 読み取れない/信頼の低い明細価格は空欄のまま。単価×数量や合計との差額で埋めず、小数点に見える区切りをカンマへ直しません。複数数量は印字から拾い、数量表記がない商品行だけ1を仮置きするため点数も要確認。税抜表記が認識できない場合は税抜欄も空欄です。
7. 分類は過去に確定した**商品名の完全一致ルールのみ**。未知の商品は未分類で、勝手に「その他」へ入れません。分類名/説明による意味分類は有料AI側だけです。税別の配賦は従来どおり、税率・金額の手確認→案→明示適用→承認が必要。無料OCRは自動配賦・自動確定しません。

環境非対応・準備失敗・タイムアウト時は手入力できます。設定画面の「利用環境あり」はMac/開発ツールの検出であり、日本語認識の成功保証ではありません。無料OCRの生データ・位置・信頼指標もローカルDBに監査保存されます。信頼指標は正答確率ではありません。

実レシート2枚をApple Visionで処理し、APIからの下書き保存/再読込まで一時DBで検証しました。1枚目は合計の区切りが `¥5.449` と認識されたため合計を未入力、低信頼価格1行も空欄。2枚目は薄い箇所を含め5行を空欄としました。完全認識は主張しません。詳しい私的結果はGit対象外の `artifacts/private-local-ocr-verification.json`（権限600）にあります。

## 有料AI OCR（任意・初期無効・OpenAI）

**実装・テスト中に有料APIは一度も呼んでいません。ライブ接続/読取精度は未検証です。**

有効化前に必ず [OpenAI公式料金表](https://openai.com/api/pricing/) でモデルの画像入力/出力料金と契約条件を確認してください。金額はモデル・画像・トークン量によって異なり、ここでは価格や1枚当たり料金を保証しません。OpenAI側で予算/通知も設定してください。アプリにハードな月額予算制限はありません。

1. このアプリ用のOpenAI APIプロジェクト/キーを用意。Hermesのキーを流用しないでください。
2. `.env.example` を `.env` にコピーし、サーバー側だけで設定：
   ```dotenv
   OPENAI_API_KEY=自分用のキー
   OPENAI_MODEL=料金を確認した画像入力とStructured Outputs対応モデルID
   LEDGER_PORT=8765
   ```
   `chmod 600 .env` を推奨。モデルは意図的に既定値を設けていません。
3. 再起動。「分類・設定」にモデル/APIキーの**有無のみ**表示。キー値はAPI/画面へ出しません。
4. 料金・画像外部送信の同意チェックを付け、「設定を保存」。チェックだけではOCRは実行されません。
5. 画像付き下書きで「有料AI OCR」を押し、送信確認に同意した時だけOpenAIへHTTP送信。

送信内容は変換済み画像と分類名/説明。`store:false` を指定しますが、これはプロバイダー側の全ログ保持をゼロにする保証ではありません。利用規約/データ方針を確認してください。OCRは画像の小さい文字や税率を誤る可能性があります。税別の税込金額は空欄として残し、印字税抜額・数量・割引/税の総額・税率を別に保持します。不明価格は逆算しません。配賦または手修正と確認が終わるまで確定できません。生の応答を監査用に保存します。再OCRは現在の明細を置き換えます。通信失敗後の手動再実行は追加料金が発生し得ます。

## OCRエラーの切り分け

- 起動ログや画像表示が200でも、`POST /api/receipts/{id}/ocr` の502は別の処理です。アプリの502だけではOpenAIのHTTPステータスは分かりません。画面の `OCR[分類]`、`HTTP ...`、`code=...`、`request_id=...` を確認してください。APIキー、画像、レシート原文、上流エラー本文を問い合わせに貼らないでください。
- `authentication` / 401：キーの有効性。`permission` / 403：プロジェクト・キー・モデルの権限。
- `quota` / 429：残高・支出上限・組織の利用上限。`credit_balance_exhausted` はAPIプリペイド残高切れで、APIの請求設定でクレジット追加が必要です。`project_spend_limit_exceeded` / `organization_spend_limit_exceeded` は各支出上限、`organization_usage_limit_exceeded` はOpenAIが設定した組織の利用上限です。残高・上限を解消するまで再実行では復旧しません。`rate_limit` / 429：利用頻度制限。code/typeで原因を識別できない429では断定せず残高・上限も確認。
- `model`：モデルの利用権限・API対応。`invalid_request`：画像入力形式・JSON Schema・指定パラメータ等を確認。上流が一般的な400しか返さない場合、モデル非対応とは断定しません。
- `timeout`：応答待ちの期限切れ（処理済み・課金済みの可能性あり）。`network`：ネットワーク、プロキシ、TLS証明書。`upstream`：OpenAI側の障害や生成失敗。
- `incomplete` / `refusal` / `invalid_response`：未完了、読み取り拒否、空または不正な応答。手入力してください。JSON応答は従来どおりローカル監査用に保存しますが、エラー表示には原文を含めません。非JSONエラー本文は保存しません。
- 設定不足は409で `OPENAI_API_KEY` / `OPENAI_MODEL` / `ocr_consent` を個別表示。`GET /api/settings` の `ocr_missing` でも確認できます。`ocr_ready` は設定・同意の確認だけで、課金枠や接続成功を保証しません。画面にも「設定済み（接続・API残高は未確認）」と表示します。
- `server.py` は起動時にこのフォルダの `.env` を `override=False` で読みます。**起動元シェルに既にある環境変数が優先**されます（空文字も優先）。`.env` 編集後は再起動が必要です。環境変数の値やキーをログへ出さず、不要なシェル設定を解除してから起動してください。モデル・ポートは自動変更しません。
- 使用形式は [Responses API](https://platform.openai.com/docs/api-reference/responses/create) の画像入力と `text.format` のJSON Schemaです。[公式GPT-5.6 Lunaモデル情報](https://developers.openai.com/api/docs/models/gpt-5.6-luna) は `gpt-5.6-luna` のResponses・画像入力・Structured Outputs対応を明記しています。モデル取得APIの200だけでは課金OCRの成功までは確認できません。モデル名を推測で変更しないでください。
- 自動再試行はありません。手動再実行は追加料金が発生し得ます。診断テストはモックだけで、実課金OCRの成功は未検証です。確定時の422は明細・合計・確認状態の検証エラーで、OCRの502とは別に内容を確認してください。

参考：[公式エラー分類](https://platform.openai.com/docs/guides/error-codes)、[Structured Outputsの未完了・拒否](https://platform.openai.com/docs/guides/structured-outputs)。

## 保存・CSV・バックアップ

- 標準データ：`data/ledger.sqlite3`、`data/images/`。SQLite整数円台帳と下書きJSON。Macのディスク自体の暗号化はFileVault等で管理してください。
- CSVは選択月の確定明細だけ。UTF-8 BOM、式注入対策あり（危険な先頭文字はアポストロフィで無害化）。
- 「画像付きバックアップ」はSQLite backup APIのスナップショットと画像をZIPへ出力。APIキー/OAuth資格情報は含みません。DBの設定やOCR全文は含みます。
- 復元：サーバーを停止→現在のdataを別名で退避→**自分が作成した信頼できるZIPのみ**を別場所に展開→ `ledger.sqlite3` と `images/` をdataへ配置→起動。認証は別途復旧/再設定。復元APIはありません。
- データ/秘密/.env/.venvは `.gitignore` 対象。バックアップやCSVを公開しないでください。

```sh
uv sync --frozen
uv run playwright install chromium
uv run pytest -q
node --check static/app.js
```

外部はMockTransport/モックadapterの契約試験。画像アップロード、HEIC変換、確認/再編集、永続化、分類編集、日次/月次集計、CSV無害化、ZIP復元、Origin/Host保護、ストリーム容量上限、税別警告、原文履歴、完全一致分類を検証します。

## 制限と今後の確認

- 実レシート2枚のローカルアップロードと手転記金額による配賦を検証済み（私的メタデータは `artifacts/private-sample-verification.json`）。2枚目の薄い価格2箇所は不明のまま保持し配賦を拒否。Apple Visionの実読み取り・下書き保存も追加検証済み（上記）。他店の精度評価、Google OAuth/Drive実アカウント、OpenAI実課金OCRの成功は未検証。
- Webの操作は単一利用者向け。多量の一覧や長いOCRは処理待ちを伴います。単一workerで起動してください。
- PDF非対応。HEICデコード可否は画像の圧縮形式にも依存します。
- 分類の削除、レシート削除、一括修正、ルール管理画面は未実装（分類の名前/説明編集と追加、レシート再編集は実装）。
- iPhone幅のChromiumでレイアウト検証済み。実iPhone Safari・リモートアクセスは未検証。iPhoneから使うには認証/TLS/公開方式を別途設計し、単にbindを広げないでください。

### 入力を楽にする操作

- 手入力の追加では今日の日付を初期表示します。購入日に合わせて変更できます。
- 通常の明細は商品名・分類・税込金額を表示。「税抜額・数量・税率・割引」を開くと詳細を編集できます。税別モードでは自動で開きます。
- 確定済みの店名・商品名を候補に表示します。商品名の完全一致ルールは未分類の欄だけに反映し、金額は再利用しません。
- 分類を選んで「未分類に適用」を押すと、分類済みの明細を保ったまま一括指定できます。
- 商品名・分類・整数の金額を入力し、金額欄でEnterを押すと次の明細へ進みます。
- 「商品の合計を使う」は手入力の転記用です。金額未入力の明細がある場合は使えません。画像がある場合は印字合計を確認してください。
- 保存・確定ボタンは入力画面の下端に表示されます。確認・承認と合計照合は従来どおり必要です。

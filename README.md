# レシート家計簿 — Mac ローカル版

日本語 / JPY。レシート画像の取り込み、無料のPaddleOCR、**必ず人が確認してから確定**する家計簿です。最初は分類以外のデータは空です。iPhone幅の画面に対応していますが、現在はMacのlocalhost専用です。

## 起動（最短）

[uv](https://docs.astral.sh/uv/getting-started/installation/) とPython 3.12以降が必要です。依存は `uv.lock` で固定しています。

```sh
cd /Users/yoshiki2357/receipt-ledger
./run.command
```

ブラウザで **http://127.0.0.1:8765** を開きます。Finderで `run.command` をダブルクリックでも起動できます。初回は依存を取得するためインターネット接続が必要です。終了はターミナルで `Ctrl+C`。

`run.command` は自分のフォルダへ移動して `uv run --frozen python server.py` を実行します。`uv` がPATHになくても `$HOME/.local/bin/uv` を探します。**0.0.0.0への公開は禁止**。8765が使用中なら `.env` の `LEDGER_PORT` を変更し、そのポートのURLを開きます。

## 基本操作

1. 「レシート」→「画像を追加」、または「手入力で追加」。JPEG/PNG/HEIC（12MiBまで、25百万画素まで）に対応。
2. 画像は画面表示・OCR用にJPEGへ変換し、EXIF回転補正、最大辺3000pxへ縮小。元ファイルはDrive/手元に残してください。アプリには変換後画像を保存します。
3. 画像から入力する場合は「画像から読み取る（無料）」でPaddleOCRを実行し、原文と画像を照合します。日付、店名、商品名、分類、**各明細の税込合計金額（数量込み）**、レシート合計を入力・修正。
4. 未完成のまま「下書きを保存」できます。税別レシートは下記の配賦案を確認して明示適用できます。通常の税込手入力では割引を負の明細で入力できます。
5. 確認チェックを付けて「確認して保存」。欠落値・小数・合計不一致では確定できません。
6. 確定後は「再編集する」で下書きへ戻せます。その間は集計対象外。
7. 「分類・設定」で分類名と説明を変更/追加。確定した商品名の完全一致ルールを次回OCR分類に優先適用します。
8. 「家計の概要」で月を選択。分類別月次・分類別日次グラフ/表を表示。支出ゼロの日も含みます。

## 画面の操作順と計算の確認

- **1. レシートを入力 → 2. 合計を確認して保存**の順です。PaddleOCRを端末内で実行します。手入力でも利用できます。
- 商品名・分類・税抜/税込明細額・数量・税率・OK割引対象には常に見えるラベルがあります。税抜/税込額は**数量込みの明細合計**で、単価ではありません。
- 通常は日付・店名・商品名・分類・税込金額・レシート合計を入力します。まとめて分類する操作は必要なときだけ開きます。
- 「商品の金額が税抜で書かれている」を選ぶと分類別の8%/10%計算を表示。OK食品割引は適用なし・3/103・印字割引額から選択し、案を見てから明示適用します。印字割引額は、その方式を選択した場合と別の計算方法を開いた場合だけ表示します。
- 従来の手動配賦は「別の計算方法：レシートの税額を使う」を開いて使用。全商品0%・8%・10%のいずれかのみで、混在税率には使えません。計算値への承認欄は詳細を開かずに操作できます。
- 入力変更後は案と承認を解除し、前回の計算は再計算が必要と表示します。税込欄は勝手に書き換えません。分類設定の変更など、保存済み計算の有効性は確定時にもサーバーで検証します。
- 保存・計算・OCR中は操作を一時停止し二重送信を防止。保存結果とエラーは確認ボタンの近くにも表示します。計算案の表示は入力を下書き保存しますが、案の適用・確定は別操作です。
- 差額0円だけでは正しい保証になりません。不明価格を差額で埋めず下書きで保存し、画像・税率・割引対象・転記額を確認してください。店舗固有の単品丸め、実iPhone Safariは未検証です。

この画面更新だけなら**ブラウザの再読み込み**で反映します。古いPython版を起動したままの場合だけ従来の再起動手順が必要です。`.env`・本番データ・税計算ルールは変更していません。

## 税別レシートの割引・税配賦

1. 「税別レシート」を選び、「別の計算方法：レシートの税額を使う」を開きます。全商品の税率（単一の0/8/10%）を印字で確認します。混在税率・不明税率はこの手動配賦では利用できません。
2. 各行に**数量込み税抜明細額**と数量を入力。割引前合計、正数の割引総額、税総額、税込合計を転記。割引後小計と点数は任意ですが入力した場合は一致検証します。不明値は空欄のまま保存してください。
3. 「商品の税込金額を確認する」は入力を下書き保存したうえで、案だけを表示します。明細額はまだ変更しません。「この金額を商品に反映する」で初めて計算値を保存します。
4. 元の税抜額、配賦割引・税、計算値の由来（`largest-remainder-v1`）を保持。配賦への承認と通常の確認チェックを付けて確定します。入力変更後は再計算が必要です。

計算は整数円の最大剰余法：割引総額を税抜額の比率で配分し、税総額を割引後金額の比率で配分。同じ剰余は明細順で優先します。合計を保存しますが、**店舗の単品別丸めや個別割引対象を再現するものではなく、家計簿上の比例配賦**です。3/103割引を3%へ置き換えません。不明価格を合計との差額で埋めません。割引超過・負の税抜額・欠落・不一致は拒否します。税率混在のグループ別配賦は未実装です。

iPhone HDR JPEGをPillowがMPOと認識する場合も主画像を取り込みます。補助画像は保存しません。

## Google Drive（任意・手動取り込み）

**既存のHermesや他アプリのトークン/秘密情報は使いません。** 自分専用のGoogle CloudプロジェクトとOAuth Desktopクライアントを作成してください。

1. [Google Cloud Console](https://console.cloud.google.com/) で自分用プロジェクトを作成/選択。
2. 「APIとサービス」→「ライブラリ」で **Google Drive API** のみを有効化。
3. Google Auth Platformの「ブランド」「対象/オーディエンス」を設定。個人利用でExternal/Testingなら自分のGoogleアカウントをテストユーザーに追加。Testing状態のトークンは期限切れになることがあります。組織アカウントは管理者の許可が必要な場合があります。
4. 「クライアント」→OAuthクライアントを作成→ **デスクトップアプリ**。Webアプリではありません。
5. JSONをダウンロードし、このアプリの `data/google-client.json` として保存。`mkdir -p data` でフォルダを作り、ファイルの権限を `chmod 600 data/google-client.json` にします。
6. このフォルダで実行：
   ```sh
   uv run --frozen python oauth_setup.py
   ```
   ブラウザが開くので自分のアカウントで許可。PKCEと動的ポートの127.0.0.1コールバックを使用します。コード/パスワードをチャットに貼らないでください。180秒でタイムアウトした場合は再実行。
7. `data/google-token.json` にこのアプリ専用トークンを権限600で保存。要求scopeは **https://www.googleapis.com/auth/drive.readonly** のみ。Drive全体への読み取り権限ですが、取り込みコードは指定フォルダの直下だけを一覧取得します。
8. Driveで対象フォルダを開き、URL `https://drive.google.com/drive/folders/FOLDER_ID` の `FOLDER_ID` 部分だけを「分類・設定」に保存。
9. 「レシート」→「Driveから取り込む」。一覧を全ページ処理。対応画像だけ取得し、下書きを作成。OCRは実行しません。

サブフォルダ/PDF/Googleドキュメントは対象外。ファイルIDおよび元ファイルSHA-256で重複排除。同じIDのファイルを更新しても再取り込みしません。エラー分は次回ボタンで再試行できます。一部取り込み後に通信失敗した場合も成功分は保持します。

認証切れ/取り消し時はセットアップを再実行。解除したい場合はGoogleアカウント側でこのアプリのアクセスを取り消し、サーバー停止後に `data/google-token.json` を削除してください。`LEDGER_DATA_DIR` を変更した場合、OAuthセットアップは標準 `data/` に保存するため、その二つの資格情報ファイルを選択したデータフォルダへ手動で移してください。

## PaddleOCR（無料・端末内で処理）

日本語のPP-OCRv5モデルをCPUで実行します。画像をOCRサービスへ送信せず、APIキーや利用料金は不要です。有料OCRのボタン・設定・APIは廃止しました。既存の画像、下書き、確定記録、OCR原文は保持します。

1. `uv sync --frozen` で依存パッケージを導入し、`./run.command` で起動します。起動済みなら一度停止して再起動してください。既存のポート設定を引き続き使います。
2. 画像付き下書きで **「画像から読み取る（無料）」** を押します。確認後、入力中の下書きを置き換えます。
3. 初回は認識モデルをダウンロードするためネット接続が必要です。画像の処理は端末内で行います。モデルはGit対象外の `artifacts/paddleocr-cache/` に保存します。認識・初回準備を合わせて300秒で打ち切ります。
4. 認識した文字と画像を照合し、店名・日付・商品名・金額・数量・分類を修正してから確定します。文字認識と明細解析には誤りがあり得ます。税込明細額と全商品の税率は自動確定しません。
5. 低信頼価格や不明額は空欄にします。単価・合計から逆算せず、未知の商品は未分類です。分類には過去に確定した商品名の完全一致ルールを使用します。税別の配賦も手確認と明示適用が必要です。

設定画面の「導入済み」はパッケージの検出です。モデル取得や認識成功を保証する表示ではありません。依存関係やモデル取得が失敗した場合は案内を表示し、手入力できます。原文・位置・信頼指標はローカルDBに保存します。信頼指標は正答確率ではありません。

### 導入確認と困ったとき

`uv.lock` で固定しているバージョンはPaddleOCR 3.7.0 / PaddlePaddle 3.3.1です。プロジェクトのフォルダで次のコマンドを実行すると、インストール済みのバージョンを確認できます。

```sh
uv run --frozen python -c 'from importlib.metadata import version; print("PaddleOCR", version("paddleocr")); print("PaddlePaddle", version("paddlepaddle"))'
```

| 状況 | 対処 |
| --- | --- |
| 「未導入」と表示される | `uv sync --frozen` の成功を確認し、起動中のサーバーを `Ctrl+C` で停止して `./run.command` で再起動します。 |
| 初回の認識が失敗・300秒でタイムアウトする | モデル取得のネット接続と `artifacts/paddleocr-cache/` への書込権限を確認してから再実行します。手入力でも続けられます。 |
| 原文は保存されたが明細を解析できない | 画面の原文と画像を見ながら、下書きに手入力します。再実行は入力中の下書きを置き換えるため、先に入力内容を確認します。 |
| 確定済みのレシートを読み取りたい | 「再編集する」で下書きへ戻してから実行します。再確定するまで集計対象外になります。 |
| 税込金額や分類が空欄になる | 不明な金額や未知の商品は空欄・未分類にします。画像で確認し、手入力または税別の配賦案を明示適用します。 |

モデルキャッシュは画像付きバックアップに含みません。別の端末への復元時やキャッシュがない場合は再取得が必要です。`LEDGER_DATA_DIR` を変更してもキャッシュはプロジェクト内の上記フォルダを使用します。認識失敗・タイムアウトでは新しいOCR履歴を作らず、認識原文の取得後に明細解析が失敗した場合は原文を保存します。

[公式PaddleOCRドキュメント](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html) のPython APIを使用します。`local_ocr.py` が保存済み画像パスを検証し、`paddle_ocr_worker.py` を時間制限付きの別プロセスで実行します。旧有料OCRの `/api/receipts/{id}/ocr` は廃止し、無料OCRの `/api/receipts/{id}/ocr/local` を使います。旧設定に含まれる同意項目は無視し、次回設定保存時には書き出しません。既存 `.env` の旧OCRキーは参照しません。

## 保存・CSV・バックアップ

- 標準データ：`data/ledger.sqlite3`、`data/images/`。SQLite整数円台帳と下書きJSON。Macのディスク自体の暗号化はFileVault等で管理してください。
- CSVは選択月の確定明細だけ。UTF-8 BOM、式注入対策あり（危険な先頭文字はアポストロフィで無害化）。
- 「画像付きバックアップ」はSQLite backup APIのスナップショットと画像をZIPへ出力。APIキー/OAuth資格情報は含みません。DBの設定やOCR全文は含みます。
- 復元：サーバーを停止→現在のdataを別名で退避→**自分が作成した信頼できるZIPのみ**を別場所に展開→ `ledger.sqlite3` と `images/` をdataへ配置→起動。認証は別途復旧/再設定。復元APIはありません。
- データ/秘密/.env/.venvは `.gitignore` 対象。バックアップやCSVを公開しないでください。

## テスト

```sh
uv sync --frozen
uv run playwright install chromium
uv run pytest -q
node --check static/app.js
```

無料OCRの追加テストは生成した日本語画像で実PaddleOCR→下書き→原文表示→編集保存をChromiumから実行します。初回モデル取得にはネット接続が必要です。

OCR関連だけを確認する場合は次を実行します。最初のコマンドは認識処理をモックに置き換える単体/API試験、二つ目は実PaddleOCRを使うブラウザ試験です。ブラウザ試験はOCRパッケージが未導入の場合にskipするため、成功件数とskipの表示を確認してください。

```sh
uv run --frozen pytest -q tests/test_local_ocr.py tests/test_paddle_worker.py tests/test_providers.py
uv run --frozen pytest -q -rs tests/test_local_ocr_browser.py
```

Playwrightテストはlocalhostの実サーバーを自動起動/停止、使い捨てディレクトリにのみfixtureを作成。`artifacts/desktop.png` / `artifacts/mobile.png` はテストデータ画面のスクリーンショットです。本番データではありません。

外部はMockTransport/モックadapterの契約試験。画像アップロード、HEIC変換、確認/再編集、永続化、分類編集、日次/月次集計、CSV無害化、ZIP復元、Origin/Host保護、ストリーム容量上限、税別警告、原文履歴、完全一致分類を検証します。

## 制限と今後の確認

- 実レシート2枚のローカルアップロードと手転記金額による配賦を検証済み（私的メタデータは `artifacts/private-sample-verification.json`）。2枚目の薄い価格2箇所は不明のまま保持し配賦を拒否。他店のPaddleOCR精度評価とGoogle OAuth/Drive実アカウントは未検証。
- Webの操作は単一利用者向け。多量の一覧や長いOCRは処理待ちを伴います。単一workerで起動してください。
- PDF非対応。HEICデコード可否は画像の圧縮形式にも依存します。
- 分類の削除、レシート削除、一括修正、ルール管理画面は未実装（分類の名前/説明編集と追加、レシート再編集は実装）。
- iPhone幅のChromiumでレイアウト検証済み。実iPhone Safari・リモートアクセスは未検証。iPhoneから使うには認証/TLS/公開方式を別途設計し、単にbindを広げないでください。

### 入力を楽にする操作

- 手入力の追加では今日の日付を初期表示します。購入日に合わせて変更できます。
- 通常の明細は商品名・分類・税込金額を表示。「税抜額・数量・税率・割引」を開くと詳細を編集できます。税別モードでは自動で開きます。
- 確定済みの店名・商品名を候補に表示します。商品名の完全一致ルールは未分類の欄だけに反映し、金額は再利用しません。
- 分類を選んで「未分類に適用」を押すと、分類済みの明細を保ったまま一括指定できます。
- 商品名・分類・整数の金額を入力し、金額欄でEnterを押すと次の明細へ進みます。
- 「商品の合計を使う」は手入力の転記用です。金額未入力の明細がある場合は使えません。画像がある場合は印字合計を確認してください。
- 保存・確定ボタンは入力画面の下端に表示されます。確認・承認と合計照合は従来どおり必要です。
